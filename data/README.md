# KKI public data (Khobz Index)

**KKI (Karama Khobz Index)** is a published reference index: the **local-currency cost of one “Khobz unit” (KK)** — roughly one adult day of staple subsistence calories (~2,200 kcal) from a **fixed regional basket** of staples. It is **not** a token, currency, or regulated instrument—the same class of artifact as the Big Mac Index or IMF published rates.

Journalists, researchers, and dashboards should use this **static archive** (open files). The live KKI HTTP API is **closed** to app traffic only at MVP; there is **no** anonymous public API tier. See [`docs/architecture/api-contract.md`](../docs/architecture/api-contract.md) §7 and [`docs/kki/kki_research.md`](../../docs/kki/kki_research.md) §7.2.

## How to get the numbers

### 1. GitHub Releases (recommended)

Each publication month `YYYY-MM` ships as:

| Asset | Role |
|-------|------|
| `khobz-index-YYYY-MM.json` | Machine-readable monthly rollup |
| `khobz-index-YYYY-MM.csv` | Flat table for spreadsheets |

**Browse releases:** `https://github.com/<org>/<repo>/releases` (replace with the canonical public repo, e.g. post-launch `The-Tech-Bay/khobz-index`).

**Direct download (pattern):**

`https://github.com/<org>/<repo>/releases/download/vYYYY-MM/khobz-index-YYYY-MM.json`

**Tag convention:** `vYYYY-MM` (e.g. `v2026-04`).

Bandwidth is served from GitHub’s CDN; **$0** for public consumers.

### 2. IPFS (content-addressed)

After each monthly publish, the JSON rollup is pinned (e.g. via Pinata). The **CID** for that month is recorded in the GitHub Release notes and accumulated in [`ipfs-manifest.json`](./ipfs-manifest.json) in this directory.

Example gateway URL (replace `CID`):

`https://ipfs.io/ipfs/CID`

### 3. Internet Archive (long-term preservation)

Items are uploaded under identifier `khobz-index-YYYY-MM`. Stable catalog page:

`https://archive.org/details/khobz-index-YYYY-MM`

Wayback coverage for the GitHub Release asset (pattern from §7.4 of the API contract):

`https://web.archive.org/web/*/https://github.com/<org>/<repo>/releases/download/vYYYY-MM/khobz-index-YYYY-MM.json`

## On-disk layout in this repo (methodology + per-country files)

**Methodology v1.0 (config)**

- [`baskets/`](./baskets/) — seven regional [`BasketVersion`](../docs/architecture/data-schema.md) JSON files.
- [`v1.0/alpha-config.json`](./v1.0/alpha-config.json) — per-country hybrid `alpha` and `market_type`.

**Per-country dual-publish (R2 + git in production)**

```text
data/{version}/{country}/{YYYY-MM}.{csv,json}
```

See [`docs/architecture/data-schema.md`](../docs/architecture/data-schema.md) §5 for the normative JSON envelope (per-country files embed `index_record` + `snapshot`) and §5.4 for **CSV columns** (`country_code`, `month`, `kki_value`, … `record_hash`).

Monthly **rollup** assets on Releases may bundle **all countries** for one month; the exact merge shape is documented in each release’s notes and must remain schema-compatible with §5.3–5.4 of the data schema.

**Operator logs (generated by the archive pipeline)**

- [`archive-log.json`](./archive-log.json) — release URL, IPFS CID, IA URL, hashes, status per month.
- [`ipfs-manifest.json`](./ipfs-manifest.json) — month → CID map (including `pending` if a pin failed).
